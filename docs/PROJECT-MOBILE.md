## 1. Цель

Слова владельца (21.09): «удобный и быстрый поиск и проверка цен для
ориентации на рынке»; «каждое поле нашей программы автоматически переносит
данные на платформы, и это должно корректно и одинаково работать для каждой
марки и модели».

Инструмент менеджера AUTOGOOD для подбора и оценки авто для клиента
(физлицо, всегда платит **брутто**):

1. **Поиск:** один набор фильтров → правильный поиск на **mobile.de**,
   **otomoto.pl** и **blocket.se** (Швеция) для поддерживаемых марок и моделей;
   неточные или непередаваемые фильтры явно отмечаются.
2. **Распознавание объявления:** ссылка mobile.de или otomoto.pl → данные авто
   заполняют форму; для импортируемого авто оцениваются доставка, осмотр и
   класс акциза для калькулятора. Польское объявление обрабатывается как
   покупка в Польше, без доставки из Германии.
3. **Анализ рынка:** реальные цены предложений трёх рынков на одном графике,
   статистика, место конкретного авто на рынке, история цен по датам.
4. **Следующий этап:** сравнивать **конкретное авто** из объявления с польским
   рынком по полной оценке «na gotowo», а не только сравнивать медианы рынков.

Критерий качества: каждый поддерживаемый фильтр переносится точно либо
помечается как пропущенный/приблизительный; выборка и её ограничения видны;
расчёт «na gotowo» согласован с калькулятором и явно отличает усреднённые
затраты от точного тарифа конкретной машины.

## 2. Правила работы для всех чатов (AI working agreement)

1. **Одно место для кода:** `/Users/nikitq/cloude/autogood-kalkulatory`
   (или временный клон, который **в тот же день** коммитится и пушится в
   `main`). Не оставлять правки незакоммиченными в других папках: всё, что не в
   `origin/main`, считается потерянным для остальных чатов.
   Перед работой: `git fetch && git status -sb`, `git pull --rebase origin main`.
   Параллельно работают несколько агентов — всегда начинай со свежего `main`.
2. **Прочитай этот документ** (разделы 4–7) и файлы, которые меняешь.
3. **Маленькие коммиты, сразу push.** Долгие незакоммиченные правки в
   `src/mobile-market-analysis.js` почти гарантируют конфликт.
4. **Кэш:** при каждом изменении файла поднимай `?v=` у его `<script>/<link>` в
   `mobile.html` (уникальная строка, напр. `feature-YYYYMMDD`). Конфликты при
   rebase чаще всего только в этих строках — бери любую новую версию.
5. **Проверка:** локальный сервер (`python3 -m http.server <порт>` из корня),
   тесты и проверка в браузере (DOM/консоль), затем push и проверка продакшна
   вместе с новыми CSS/JS-ресурсами. Pages и браузерный кэш обновляются не
   одновременно. Если `node` не в `PATH`, использовать runtime Codex или
   другой установленный Node; не пропускать тесты молча. На Mac владельца
   `node` в `PATH` нет; есть Node из Codex:
   `~/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node`
   (он же запускает импортер). Запасной путь — запустить `scripts/*.mjs` в
   браузере на локальном сервере с заглушками `fs`/`vm`/`assert`. Аудиты
   Blocket и av.by — на Python (`scripts/audit-*.py`).
6. **Визуальные изменения крупнее мелочи — сначала варианты владельцу,**
   он выбирает. Баги — чинить сразу и выкладывать, если не ломает работу.
7. **Не перетирай чужие решения молча.** Если меняешь поведение, введённое
   другим агентом (см. «Решения»), — запиши причину в журнал.
8. **После изменения:** добавь строку в «Журнал изменений» (дата, агент,
   что и зачем, коммит), обнови статус в «Бэклоге», новые решения — в «Решения».
   Колонка «Коммит»: хэш, если код закоммичен раньше документа; если код и
   документ в одном коммите — «этот коммит», куратор потом проставляет хэш
   (`git log --reverse --format=%h -S'<начало строки>' -- docs/PROJECT-MOBILE.md`).
9. Коммиты: понятное сообщение «что и зачем»; подпись агента по его правилам.
10. **Статусы не смешивать:** код в `main`, живой GitHub Pages, запущенный
    локальный backend и работающий quick tunnel — четыре отдельные проверки.
    Не обещать доступность для всех лишь по факту push. Этот файл — общий для
    обоих агентов, но будущие чаты должны открыть его и записать свой результат.
11. **Параллельные чаты в одной копии.** Если `git status` показывает правки
    или коммиты, которых ты не делал, — это работа другого чата: не трогай,
    не коммить и не пушь её. Работай в отдельной копии
    `git worktree add ../ag-<тема> origin/main`, свой код держи по возможности
    в отдельных файлах, затем `git pull --rebase origin main` и push в `main`.

12. **Как писать в этот документ.** Перечитай нужный раздел прямо перед

## 4. Механизмы (как это работает)

> Перенос фильтров на три площадки полностью описан в
> **`docs/FILTERS-MOBILE-OTOMOTO.md`**. Здесь кратко.

### 4.1 Поиск mobile.de
- URL `suchen.mobile.de/fahrzeuge/search.html` с **числовыми ID**
  `ms=<make>;<model>;<group>;<text>`. SEO-маршрут `/auto/…` теряет все фильтры.
- ID берутся из `m.mobile.de/svc/r/makes/Car` и `/svc/r/models/<makeId>`
  (группы `"g":true` идут 3-м сегментом). Генератор
  `tools/generate-mobile-de-ids.py` получает 403 на пачках запросов →
  `--from dump.json` (сохранённый ответ).
- Поле «Wersja» — свободный текст (напр. «S line»), уходит 4-м сегментом `ms`.
  У otomoto аналога нет.
- Контракт параметров встроен в HTML страницы поиска (`"blt":{"type"`).
  Неверный параметр молча игнорируется. Проверка: `numResultsTotal`.

### 4.2 Поиск otomoto
- `otomoto.pl/osobowe/<make>/<model>?search[...]`, модели через
  `matchedOtomotoModels` / `otomotoModelAliases` / `otomotoModelFallback`.
- Цена фильтра переводится EUR→PLN по курсу из `data/exchange-rates.json`
  (`eurPlnRate()`, не живой курс, см. B12).
- Страна продавца **не** отправляется как `filter_enum_country_origin`
  (другое значение, резало выдачу).

### 4.2b Поиск blocket.se (Швеция)
- `blocket.se/mobility/search/car?variant=…` — те же параметры принимает JSON-API
  `…/api/search/SEARCH_ID_CAR_USED`, который перечисляет применённые фильтры.
- Цена в SEK (Walutomat EURPLN / SEKPLN), пробег в шведских милях (км / 10),
  лизинг исключён (`sales_form=1,2`). Подробно — справочник фильтров, раздел 5b.
- Счётчик «Aktualne oferty» и анализ читают API через `r.jina.ai`.
- Анализ: до 8 страниц по 50 равномерно по списку; при > 2 500 объявлений
  дальняя половина читается с дорогого конца (`PRICE_DESC`), место =
  всего − позиция + 1. Цены хранятся в SEK, пробег переводится в км (mil × 10).
  Подозрительные слова дополнены шведскими (skadad, motorfel, reservdel,
  leasingöverlåtelse…).

### 4.2c Поиск av.by (Беларусь)
- Открытый API `api.av.by` (CORS `*`, без прокси): `POST /offer-types/cars/filters/main/apply`
  со списком свойств; ответ — число, страницы по 25, объявления и **готовая ссылка
  самого av.by** на этот поиск (`seo.currentPage.url`); `initialValue` — принятые фильтры.
- Наша ссылка `cars.av.by/filter?…` строится так же, как пишет её av.by: проверено
  на 138 вариантах формы — совпадает параметр в параметр.
- Цена: форма в EUR → `price_usd` (Walutomat EURPLN / USDPLN). Объявления —
  своя цена в USD (как у av.by), «под ключ» для av.by **не считается** (решение 10-02).
- av.by отвечает 429 на пачку запросов: все запросы идут по очереди, ≥ 0,7 с, с повтором.
- Объявление по ссылке: `GET api.av.by/offers/<id>`. Стр. 4: «новые» = сортировка 4.
- Сайт cars.av.by показывает проверку «Confirm You Are Human» роботам — данные
  берутся только из API. Подробно — справочник фильтров, раздел 5c.

### 4.2d Франция — AutoScout24 FR (с 10-04, B47)
- Рынок `autoscoutfr` = «Francja»: стр. 1 (логотип AutoScout24 с флагом FR, счётчик —
  только пока Франция включена, ссылка), анализ (своя строка статистики, свой график,
  вывод «z Francji», «na gotowo», «под ключ в Минск» в режиме «Беларусь»), Monitoring
  (своя строка цены od/do, плитка, полный список до 2000), история цен. По умолчанию
  выключен («+» на логотипе), как Blocket и av.by.
- Фильтры — те же, что у AutoScout24 в Германии (FILTERS-MOBILE-OTOMOTO.md §5e, 28
  проверок по числу объявлений). Ссылка на объявление AutoScout24 французской машины
  (любой домен) переключает сравнение на «Francja».
- Проверено 10-04: VW Golf дизель 2019–2021 — счётчик 101, анализ «Francja» 101
  предложение, медиана ~95 000 zł na gotowo против Niemcy 78 850 zł и Polska 55 999 zł;
  Monitoring — 101 объявление, полный список.

### 4.3 Распознавание ссылки
- **mobile.de:** «Rozpoznaj» обрабатывает ссылку **внутри текущей страницы**.
  `readMobileDeApiUrl()` выбирает URL из `window.AUTOGOOD_MOBILEDE_API_URL`,
  параметра `mobiledeApi` либо встроенного временного адреса; `fetch` запрашивает
  `/mobilede/import`. Сервер нормализует ID/URL, читает объявление браузером
  Chrome (CDP), запрашивает немецкую версию страницы (`lang=de`) и возвращает
  цену брутто/нетто при наличии, авто, двигатель, пробег, год, продавца и
  местоположение. Если backend недоступен, показывается резервная закладка,
  данные приходят через `mobile-bridge.js`; доступ к mobile.de не гарантирован
  самим наличием туннеля.
- **otomoto.pl:** переключатель mobile.de / otomoto.pl у поля ссылки
  (переключается сам по адресу). Объявление читается через прокси
  `r.jina.ai` (`x-respond-with: html`) из `__NEXT_DATA__ → advert`.
  Цена в PLN (+ экв. EUR), без доставки из Германии.
- Распознанное авто заполняет форму. Диапазоны сравнения: год — точный
  (правка Codex `adef7fd`), мощность ±10%, объём ±100, пробег свободный.
  Это авто отмечается ромбом на графике анализа. Рядом с ценой распознанного
  объявления (кроме otomoto и av.by) — кнопка **«Oblicz na gotowo»** (B42, 4.6.3 п. 16).
- **blocket.se:** третий вариант «Link ogłoszenia» (с 29.09): объявление
  читается через прокси (schema.org Product: цена SEK; «Modellår/Miltal/
  Växellåda/Drivmedel/Biltyp/Drivhjul»), мили × 10 → км, транспорт по тарифу
  «другая Европа». Живая проверка на нескольких объявлениях не записана (B30).
- **av.by:** `GET api.av.by/offers/<id>` (4.2c).
- **AutoScout24 (с 10-04, B48):** пятый вариант у поля ссылки; любой домен,
  ID → `www.autoscout24.de/angebote/<ID>` через прокси; брутто, нетто и ставка НДС,
  объём, мощность, коробка, привод, месяц регистрации, оснащение, продавец
  (подробно FILTERS-MOBILE-OTOMOTO.md §5d). Рынок сравнения — AutoScout24,
  «To auto» стоит на его графике. Проверено: Passat Variant 11 400 € (нетто 9 580,
  НДС 19 %), ссылки .de и .nl.

### 4.3.1 Как тестировать через временный туннель

- Локальный импортер: LaunchAgent `com.autogood.mobilede-import`, порт
  `127.0.0.1:8788`. `GET /mobilede/import` без параметра `url` отвечает
  ожидаемым HTTP 400; `OPTIONS /mobilede/import` — HTTP 204 с CORS. Отдельного
  `/health` у этого сервиса нет.
- Туннель: LaunchAgent `com.autogood.mobilede-cloudflared`. Когда адрес
  `*.trycloudflare.com` перестал разрешаться или отвечает `Tunnel not found`,
  выполнить `launchctl kickstart -k gui/$(id -u)/com.autogood.mobilede-cloudflared`,
  взять **новый** адрес из `~/Library/Logs/autogood-mobilede-cloudflared.err.log`
  и проверить снаружи `GET /mobilede/import` (ожидаемый HTTP 400).
- **Как импортер читает mobile.de.** mobile.de отказывает серверам, прокси и
  headless Chrome (даже с cookies), но не настоящему Chrome. Импортер держит
  Chrome со своим профилем (CDP `127.0.0.1:9333`); фоновая вкладка на
  `suchen.mobile.de/robots.txt` делает `fetch()` объявлений (`lang=de`) и
  страниц поиска — отрисованные страницы mobile.de в фоновых вкладках
  замирают. На «Access denied» он ненадолго показывает www.mobile.de в своём
  окне, чтобы обновить bot-cookie. Поэтому из датацентра в нынешнем виде
  работать не будет (учесть в B6).
- **Импортер запускается из основной копии.** LaunchAgent вызывает
  `server/mobilede-import.mjs` из `/Users/nikitq/cloude/autogood-kalkulatory`
  через Node из Codex (см. §2 п. 5). Правка сервера в другой копии не действует,
  пока основная копия не обновлена (только если она чистая) и не выполнен
  `launchctl kickstart -k gui/$(id -u)/com.autogood.mobilede-import`.
- **Адрес туннеля в код не записывается** (решение владельца 03.10):
  `DEFAULT_MOBILEDE_API_URL` в первой строке `src/mobile.js` больше не меняют
  после перезапуска туннеля; тестовый адрес передаётся только через
  `?mobiledeApi=`. Следствие: без параметра распознавание mobile.de у
  пользователей работает, только пока жив старый адрес — постоянное решение B6.
- Открыть `mobile.html?mobiledeApi=<URL-encoded https://новый-адрес/mobilede/import>`.
  Прогнать **реальное** объявление и `/mobilede/search` с теми же фильтрами;
  один ответ 400 без URL подтверждает только маршрут, не качество данных.
  Если адрес пока не разрешается локально, сначала проверить DNS через
  `dig @1.1.1.1`; не записывать адрес туннеля в постоянную конфигурацию.

### 4.4 Закладка «AUTOGOOD ↦ mobile.de»
- Это резервный путь, который показывается, когда импортер недоступен.
  Mobile.de может блокировать автоматические запросы (403); закладка
  работает в браузере пользователя и тоже требует живой проверки.
- На объявлении: JSON-LD `@type: Car` + `data-testid` → данные авто.
- На списке: Next.js flight data (`self.__next_f`, двойное кодирование),
  20 предложений на страницу, максимум 100 страниц на сортировку. Выборка — 8
  страниц равномерно по списку, дальний конец читается через `od=down`,
  место = `total − позиция`. Полное название — из `h2` карточки. Для «под
  ключ» сохраняются страна, индекс, город, кузов, объём, топливо, мощность.
- Доставка данных: `window.opener.postMessage` (если открыто из AUTOGOOD)
  или `mobile.html#autogood-import=<json>`. Приём только от
  `https://(suchen|www|m).mobile.de`.
- **Закладка — копия кода на момент перетаскивания.** После изменений
  закладки её надо перетащить заново.

### 4.6 История поисков, избранное, история цен
- Страница 1: история обычных поисков под формой; после изменения фильтров
  запись создаётся/обновляется с задержкой. Избранные поиски закреплены в
  общей полосе и доступны на странице 4; ★ добавляет/убирает избранное,
  не удаляя обычную историю. Выбор избранного остаётся на текущей странице.
- Выбранная запись истории/избранного + реальные изменения фильтров или
  сравниваемых рынков → «Gotowe» сохраняет изменения в ту же запись.
- **История цен:** каждая проверка (открытие поиска с загрузкой или
  «Odśwież dane») = **новая строка** с датой и временем на странице 3.
  История **полная и никогда не обрезается** (лимита нет, решение владельца
  29.09). Смена фильтров избранного (кроме рынков) не стирает замеры: в журнал
  добавляется отметка `{at, filtersChange: true, filters}`, в таблице — серая
  строка «Od tego pomiaru zmienione filtry», сравнение через неё не идёт.
  Авто выбирается только в общей полосе избранного сверху (своего выбора на
  странице 3 нет). Точка mobile.de/AutoScout24 хранит, кроме `turnkey` (PLN,
  «na gotowo»), `turnkeyBy` (с 10-03, B52): `{currency: "USD", count, median,
  p25, p75, min, max}` «под ключ с растаможкой» в Минске — по ней строки и
  график в режиме «Беларусь» (4.7b). Под названием авто — «Porównywane rynki» (выбор на
  странице 1); **отдельная таблица на каждый выбранный рынок**, одна под
  другой (PL → DE → SE): один рынок — одна таблица, два — две. Стрелки:
  цены вниз / предложений больше — зелёные (`isGood`), наоборот — красные
  (`isBad`). Переключатель «Automatyczna aktualizacja» (codziennie / co 3 dni /
  co tydzień) хранится в записи как `autoRefresh: {enabled, every}` и в
  резервной копии избранного; сами автозамеры ждут сервер (B5).
- **Объявления каждой проверки (с 30.09):** при каждой новой строке истории
  (или дополнении проверки другим рынком) её объявления пишутся в IndexedDB
  `autogood-mobile-check-offers`, хранилище `checks`, ключ `<historyId>|<at>`:
  `{historyId, at, markets: {<рынок>: {total, complete, offers: [{key, url,
  title, price, currency, year, mileage, rank, turnkey, suspect}]}}}`.

### 4.6.1 Сохранность избранного и истории — ОБЯЗАТЕЛЬНЫЕ правила

Инцидент 2026-09-27: у владельца пропали избранные поиски/авто. Прочитать
хранилище Chrome с диска для восстановления не удалось (нет доступа).
Причины, найденные в коде (до исправления):

1. **Устаревшая вкладка затирала всё.** История читалась из `localStorage`
   один раз при открытии вкладки, а каждое изменение (в т.ч. **автоматическая
   запись каждого поиска**) записывало в хранилище весь массив из памяти.
   Две вкладки mobile.html (например, вторая открылась через закладку
   `#autogood-import=…`) → ★ в одной вкладке, потом любой поиск в другой →
   избранное из первой исчезало. Самый вероятный сценарий.
2. **Нечитаемая история = пустая история.** Любая ошибка чтения/разбора
   давала `[]`, и следующий авто-лог поиска перезаписывал хранилище.
3. **Переполнение `localStorage` (~5 МБ).** У каждой записи до сотен
   предложений; при переполнении запись просто не сохранялась.
4. **Другой адрес = другое хранилище.** `localStorage` привязан к адресу:
   `belovn1999-rgb.github.io`, `localhost:<порт>` (каждый порт отдельно),
   другой браузер/профиль Chrome — у каждого своё избранное. Очистка данных
   сайта / режим инкогнито тоже стирают его.

Что сделано (`src/mobile-market-analysis.js`) и что **нельзя ломать**:

- `refreshMarketHistory()` — **каждая** функция, меняющая историю
  (`createMarketSnapshot`, `updateMarketSnapshot`, `setHistoryPinned`,
  `deleteHistoryEntry`, `toggleCurrentHistoryFavorite`, `logSearchToHistory`),
  сначала перечитывает хранилище. Новая функция записи → тоже.
- Событие `storage`: изменения из другой вкладки сразу видны в этой.
- `storeMarketHistory` сначала пишет резервную копию избранного
  `autogood.mobile.marketFavorites.v1` (маленькая, без предложений), потом
  историю; при переполнении по очереди убирает списки предложений у старых
  и затем у всех **неизбранных** записей. Избранное не удаляется никогда.
- `loadMarketHistory` возвращает избранное из резервной копии, если в
  истории его нет. Нечитаемая история копируется в
  `autogood.mobile.marketHistory.broken.<время>` до любой новой записи.
- **Запрещено:** менять ключи хранилища без миграции старых; вызывать
  `localStorage.clear()`/`removeItem` для этих ключей; писать в хранилище
  массив, загруженный давно, а не перечитанный; фильтровать при загрузке
  записи так, что они потом перезапишутся (новое поле фильтра → записи без
  него должны читаться).
- Работать владельцу **только** с https://belovn1999-rgb.github.io/autogood-kalkulatory/mobile.html
  в одном и том же профиле Chrome; localhost — только для тестов.
- Полная защита (перенос между браузерами/устройствами, очистка данных) —
  только экспорт/импорт или сервер: бэклог B25, B26.

### 4.7 Курс и «na gotowo»
- **Акциз по объявлению (с 10-03):** `engineInfo()` в `turnkey-estimate.js` — объём из выдачи (mobile.de `attr.cc`, AutoScout24 `engineDisplacementInCCM`), из прочитанного объявления (`AUTOGOOD_AD_DETAILS`), из названия («2.0 TDI», «1,5 T-GDI»), затем из фильтров, иначе ≤ 2000 см³ и сноска «Bez pojemności…». Топливо — из поля топлива объявления (не из названия); гибрид — любое упоминание в топливе или названии, включая mild (MHEV, 48V, eTSI, EQ Boost); plug-in ≤ 2000 см³ — 0 %. Анализ дочитывает объявления mobile.de без объёма в фоне.
- **Курс до ответа Walutomat:** файл + маржа; когда приходит живой курс, `turnkey-estimate.js` шлёт `autogood:rates`, открытый анализ пересчитывается.
- Курс = курс калькулятора: **Walutomat, лучшая цена продажи EUR→PLN**
  (`AUTOGOOD_TURNKEY.calculatorRate()`), запасной — `data/exchange-rates.json`.
- **Курсы в шапке и ежедневный файл (с 10-04, B12, владелец):** слева от PL/RU —
  все пары, которыми считает страница (`src/mobile-rates.js`): 1 EUR и 1 SEK в zł
  (курс калькулятора, Walutomat + 0,02), 1 USD в zł (Walutomat), НБРБ: 1 USD и
  1 EUR в BYN; во всплывающей подсказке — курсы Walutomat без маржи, время и
  источник. Эти же значения идут в пересчёт (цены, фильтр цены, «na gotowo»,
  «под ключ» в Минск). Если источник не отвечает — **файл дня**
  `data/exchange-rates.json` (EUR/SEK/USD → PLN + `nbrb` EUR/USD/PLN → BYN),
  его каждое утро (04:15 UTC, до мониторинга в 9:00) пишет
  `.github/workflows/exchange-rates.yml` (`scripts/update-exchange-rates.mjs`).
  Открытая страница в новый день спрашивает все курсы заново и пересчитывает.
- `turnkeyDirect()` = формула вкладки «Zakup bezpośredni» калькулятора:
  авто×курс + осмотр и транспорт (+VAT 23%) + акциз по классу двигателя
  + комиссия AUTOGOOD (1829,27 + 1%, +VAT) + TO 150 + перевод 250.
  **Без регистрации, без скидки**, итог округляется до 50 PLN.
  Сверено с калькулятором.
- `turnkeyForListing()` берёт тариф доставки/осмотра по стране и индексу
  продавца и класс акциза по топливу/объёму.
- **Константы — копия `src/main.jsx`. Меняешь калькулятор — меняй и модуль.**
- **Курс с маржой калькулятора (с 09-28):** EUR = Walutomat + 0,02 zł, округление
  до гроша (`rateWithCalculationMargin` в `main.jsx`); SEK — та же маржа в
  пропорции (`currentRates()`). Этот курс помечен `calculator: true` и
  `data/exchange-rates.json` его больше не перезаписывает. Им считаются график,
  статистика и «na gotowo».
- **«~ na gotowo» в анализе (с 09-28, решение владельца; раньше «pod klucz»):** для каждого
  предложения mobile.de и blocket.se — `turnkeyAverage()`: формула калькулятора
  с **усреднёнными** доставкой 2 500 zł нетто и осмотром 1 500 zł нетто (не тариф
  продавца), акциз по классу двигателя (`engineClassFor`: топливо и объём
  объявления, иначе из фильтров; шведские «laddhybrid/el/bensin» понимаются),
  услуга AUTOGOOD (1 829,27 + 1%) × 1,23 = 2 250 zł + 1,23%, ТО 150 + перевод 250.
  Показывается в статистике, таблице предложений и подсказках. На графике
  иностранные точки и их медианы стоят **непосредственно** по цене «na gotowo»
  в PLN; прежней отдельной пунктирной медианы нет. История цен сохраняет
  медиану «na gotowo» для DE/SE (старые замеры получают оценку из прежней
  медианы). Для PL остаётся цена объявления. Под графиком — сноска о расчёте
  и **вывод из данных** (с 10-03 — бриф: «takie samo auto» при ≥ 20 предложениях на рынок, иначе медианы; < 8 — «Za mało ofert»; пробег; преимущества; разбивка «na gotowo» медианного авто; otomoto отдельно — CEPiK и пригнанные): иностранная медиана «na gotowo» против медианы Польши,
  текст «taniej» или «drożej» по фактическому сравнению.

### 4.7b «Под ключ» в Беларусь (mobile.de → Минск) — `src/turnkey-belarus.js`
Формула калькулятора белорусского офиса (autogood.by/tools/auto-calculator-from-europe,
сервер `autogood.by/calc/calc-tax.php`), сверена 03.10 на **99 случаях — совпадение
до цента** (пошлина, утильсбор, итог € и $). Отличия по решению владельца:
доставка = средний транспорт до Польши из польского калькулятора (2 500 PLN нетто)
+ Варшава–Минск 600 €; услуги AUTOGOOD.BY 825 BYN (на сайте 870 / 1 120 BYN).
- Цена авто: **нетто**, если в объявлении есть цена нетто; иначе брутто.
- Пошлина (€): 3–5 лет — €/см³: ≤1000 1,5; ≤1500 1,7; ≤1800 2,5; ≤2300 2,7; ≤3000 3,0; >3000 3,6.
  Старше 5 лет: 3,0 / 3,2 / 3,5 / 4,8 / 5,0 / 5,7. До 3 лет — max(% цены, €/см³):
  ≤8 500 € 54 %/2,5; ≤16 700 48 %/3,5; ≤42 300 48 %/5,5; ≤84 500 48 %/7,5;
  ≤169 000 48 %/15; выше 48 %/20. Электромобили — пошлина 0, таможенный сбор 0.
- Утильсбор: до 3 лет 624,92 BYN, старше 1 282,02 BYN. Сборы: таможенный 120,
  декларант 350, склад 110, ЭПТС 170, AUTOGOOD.BY 825 BYN.
- Льгота 50 % (Указ №140) по умолчанию **не** применяется; экономия с льготой
  считается отдельно (`benefitSavingUsd`) для сноски.
- Курсы — официальные НБРБ (`api.nbrb.by/exrates/rates/{EUR,USD,PLN}?parammode=2`),
  они же для цен av.by. Пример: 10 000 € нетто, 1498 см³, 3–5 лет → 14 561,66 € =
  16 407,37 $ (НБРБ 03.10).

**Три цены у каждого авто из Германии** (решение владельца 03.10) — в таблице
объявлений, подсказке точки, статистике и в «Мониторинге»:
1. «Цена авто» — нетто, если продавец выделяет НДС (mobile.de: цена нетто из
   объявления; AutoScout24: брутто с «¹» ÷ (1 + НДС страны), в Германии ÷ 1,19),
   иначе брутто; в € и $.
2. «С доставкой до Минска» — цена авто + доставка до Польши (средняя) +
   Варшава — Минск 600 € + услуги AUTOGOOD 825 BYN.
3. «Под ключ с растаможкой» — плюс пошлина, утильсбор, таможенный сбор,
   декларант, склад, ЭПТС (по ней стоят точки графика и сравнение рынков).
Режим «Беларусь» работает для **mobile.de и AutoScout24** (пятый портал, только
объявления, которых нет на mobile.de): у каждого своя строка статистики, свой
график и своя фраза вывода. Объём и месяц регистрации AutoScout24 — прямо из
выдачи (`engineDisplacementInCCM`, `tracking.firstRegistration`), mobile.de — из
каждого объявления. При av.by в сравнении страница открывается на русском
(и после перезагрузки); RU: «км», «л. с.».

**Анализ в режиме «Беларусь»** (в сравнении есть mobile.de и av.by): график и
статистика в USD; точки mobile.de — «под ключ РБ» по `turnkey-belarus.js`, av.by —
BYN объявления ÷ курс НБРБ; вывод «из Германии под ключ в Минске на X $ (Y %)
дешевле/дороже, чем на av.by»; сноска на русском/польском: состав цены, ставки по
возрасту и объёму, курс НБРБ на дату, экономия с льготой 50 % (медиана), проверка
точной даты производства для 3–5 лет, «точную стоимость рассчитает менеджер».
**Данные mobile.de прямо из выдачи (с 10-03, B52):** импортер отдаёт месяц и год
1-й регистрации (`attr.fr` «12/2020» → `firstRegistration`) и объём (`attr.cc`).
Отдельной цены нетто в выдаче нет (`price.grs` — только брутто, и при `vat=1`), но
есть признак НДС «¹» (`vatDeductible`): нетто = брутто ÷ (1 + НДС страны) — совпадает
с нетто в объявлении (3 из 3, напр. 17 490 € ÷ 1,19 = 14 697,5 против 14 697).
Проверено на живой выдаче: месяц у 24 из 24, объём у 21 из 24, «¹» у 6.
По одному (`mobile-ad-details.js`, ≈ 1 с на объявление, дальше из кэша; график
дополняется по ходу, «Уточняю …: N из M») читаются только объявления без объёма
или без месяца регистрации — после перезапуска импортера это ~1 из 8, до него все.
Пока объём неизвестен —
объём из фильтра (диапазон) или распознанного авто той же модели, иначе
объявление не показывается («без известного объёма: N»). Проверено 03.10:
VW Passat diesel 2019–22 — 144 из 147 объявлений, 5 сверены вручную до доллара.

- `robots.txt`: **Crawl-delay: 30** — не чаще одной страницы в 30 с. Полная

- Структура: марка `/car-specs/<Brand>-models` → модель
  `/car-specs/<Brand>-models/<Brand>-<Model>` (поколения `<h2>Имя (год - год|Present)</h2>`,
  кузова со ссылкой и «N Versions») → кузов `/car-specs/<Brand>/M<id>/<имя>`
  (таблицы `versions_div` по топливу: Petrol / Diesel / Plugin Hybrid…;
  строка = название, год, «hp / kW», «cm³»).
- Данные берутся как есть; найденные ошибки источника перечисляются в начале
  `docs/MODEL-*.md` (снятые модели с «н. в.»: Mondeo 5, S-Max 2, Auris 2,

- Годы ultimatespecs — модельные; рестайлинг — отдельное поколение; годы

## 9. Риски и ограничения

- **ultimatespecs.com** — чужой сайт без API: Crawl-delay 30 с (пересборка — часы), может сменить разметку или закрыться; в данных есть ошибки (§4.8). Готовые таблицы лежат в репозитории, фильтры не должны ходить на сайт в реальном времени.
- **Параллельные правки** одного файла несколькими агентами → конфликты;
  см. правила в разделе 2.
- `r.jina.ai` — бесплатный внешний прокси: ограничения/отказ = нет данных otomoto.
  Лимит 20 запросов в минуту **с одного адреса** (все вкладки и программы
  офиса вместе); очередь B64 держит 18 в минуту на браузер, поэтому мониторинг
  с «Dodatkowe» и полным AutoScout24 идёт минуты. Снимает — свой прокси (B11).
- Сервер mobile.de на quick tunnel — адрес меняется при каждом запуске.
- Закладку нужно перетаскивать заново после изменений.
- История и избранное в `localStorage`: не переносятся между браузерами/устройствами/адресами, пропадают при очистке данных сайта — до B25/B26 (см. 4.6.1).
- Цены объявлений ≠ цены сделок.
- `node` есть только внутри runtime Codex: обновление Codex может сдвинуть путь,
  и LaunchAgent импортера перестанет запускаться.
- Адрес quick tunnel в `src/mobile.js` больше не обновляется (решение 03.10):
  после перезапуска туннеля распознавание mobile.de без `?mobiledeApi=` не
  работает до B6.
- Документ растёт: когда журнал §7 снова станет длинным, переносить старые
  месяцы в `docs/archive/` (так сделано 03.10 для сентября).

## 10. Глоссарий

- **Na gotowo** — оценка полной цены иностранного авто после доставки в PL
  для физлица; в анализе рынка доставка и осмотр усреднены, а не подтверждены
  по конкретному продавцу. Ранее интерфейс называл это «pod klucz».
- **Под ключ (pod klucz)** — стоимость авто, доставленного и готового в PL
  для физлица, по формуле «Zakup bezpośredni», без регистрации.

- **Проверка** — одна загрузка цен рынка (строка в «Historia cen»).
- **Закладка** — bookmarklet «AUTOGOOD ↦ mobile.de».
