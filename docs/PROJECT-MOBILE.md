## 1. Цель

Инструмент менеджера AUTOGOOD для подбора и оценки авто для клиента
(физлицо, всегда платит **брутто**):

1. **Поиск:** один набор фильтров → правильный поиск на **mobile.de**,
   **otomoto.pl** и **blocket.se** (Швеция) для поддерживаемых марок и моделей;
   неточные или непередаваемые фильтры явно отмечаются.
2. **Распознавание объявления:** ссылка mobile.de или otomoto.pl → данные авто
   заполняют форму; для импортируемого авто оцениваются доставка, осмотр и
   класс акциза для калькулятора. Польское объявление обрабатывается как
   покупка в Польше, без доставки из Германии.
3. **Анализ рынка:** реальные цены предложений трёх рынков на одном графике,
   статистика, место конкретного авто на рынке, история цен по датам.
4. **Следующий этап:** сравнивать **конкретное авто** из объявления с польским
   рынком по полной оценке «na gotowo», а не только сравнивать медианы рынков.

Критерий качества: каждый поддерживаемый фильтр переносится точно либо
помечается как пропущенный/приблизительный; выборка и её ограничения видны;
расчёт «na gotowo» согласован с калькулятором и явно отличает усреднённые
затраты от точного тарифа конкретной машины.

## 4. Механизмы (как это работает)

> Перенос фильтров на три площадки полностью описан в
> **`docs/FILTERS-MOBILE-OTOMOTO.md`**. Здесь кратко.

### 4.1 Поиск mobile.de
- URL `suchen.mobile.de/fahrzeuge/search.html` с **числовыми ID**
  `ms=<make>;<model>;<group>;<text>`. SEO-маршрут `/auto/…` теряет все фильтры.
- Поле «Wersja» — свободный текст (напр. «S line»), уходит 4-м сегментом `ms`.
  У otomoto аналога нет.
- Контракт параметров встроен в HTML страницы поиска (`"blt":{"type"`).
  Неверный параметр молча игнорируется. Проверка: `numResultsTotal`.

### 4.2 Поиск otomoto
- `otomoto.pl/osobowe/<make>/<model>?search[...]`, модели через
  `matchedOtomotoModels` / `otomotoModelAliases` / `otomotoModelFallback`.
- Цена фильтра переводится EUR→PLN по курсу из `data/exchange-rates.json`
  (`eurPlnRate()`, не живой курс, см. B12).
- Страна продавца **не** отправляется как `filter_enum_country_origin`
  (другое значение, резало выдачу).

### 4.2b Поиск blocket.se (Швеция)
- `blocket.se/mobility/search/car?variant=…` — те же параметры принимает JSON-API
  `…/api/search/SEARCH_ID_CAR_USED`, который перечисляет применённые фильтры.
- Цена в SEK (Walutomat EURPLN / SEKPLN), пробег в шведских милях (км / 10),
  лизинг исключён (`sales_form=1,2`). Подробно — справочник фильтров, раздел 5b.
- Счётчик «Aktualne oferty» и анализ читают API через `r.jina.ai`.
- Анализ: до 8 страниц по 50 равномерно по списку; при > 2 500 объявлений
  дальняя половина читается с дорогого конца (`PRICE_DESC`), место =
  всего − позиция + 1. Цены хранятся в SEK, пробег переводится в км (mil × 10).
  Подозрительные слова дополнены шведскими (skadad, motorfel, reservdel,
  leasingöverlåtelse…).

### 4.3 Распознавание ссылки
- **mobile.de:** «Rozpoznaj» обрабатывает ссылку **внутри текущей страницы**.
  `readMobileDeApiUrl()` выбирает URL из `window.AUTOGOOD_MOBILEDE_API_URL`,
  параметра `mobiledeApi` либо встроенного временного адреса; `fetch` запрашивает
  `/mobilede/import`. Сервер нормализует ID/URL, читает объявление браузером
  Chrome (CDP), запрашивает немецкую версию страницы (`lang=de`) и возвращает
  цену брутто/нетто при наличии, авто, двигатель, пробег, год, продавца и
  местоположение. Если backend недоступен, показывается резервная закладка,
  данные приходят через `mobile-bridge.js`; доступ к mobile.de не гарантирован
  самим наличием туннеля.
- **otomoto.pl:** переключатель mobile.de / otomoto.pl у поля ссылки
  (переключается сам по адресу). Объявление читается через прокси
  `r.jina.ai` (`x-respond-with: html`) из `__NEXT_DATA__ → advert`.
  Цена в PLN (+ экв. EUR), без доставки из Германии.
- Распознанное авто заполняет форму. Диапазоны сравнения: год — точный
  (правка Codex `adef7fd`), мощность ±10%, объём ±100, пробег свободный.
  Это авто отмечается ромбом на графике анализа.
- **blocket.se:** отдельный поиск и рыночная выборка работают, но ссылка на
  конкретное объявление через «Link ogłoszenia» пока **не распознаётся** (B30).

### 4.4 Закладка «AUTOGOOD ↦ mobile.de»
- Это резервный путь, который показывается, когда импортер недоступен.
  Mobile.de может блокировать автоматические запросы (403); закладка
  работает в браузере пользователя и тоже требует живой проверки.
- На объявлении: JSON-LD `@type: Car` + `data-testid` → данные авто.
- На списке: Next.js flight data (`self.__next_f`, двойное кодирование),
  20 предложений на страницу, максимум 100 страниц на сортировку. Выборка — 8
  страниц равномерно по списку, дальний конец читается через `od=down`,
  место = `total − позиция`. Полное название — из `h2` карточки. Для «под
  ключ» сохраняются страна, индекс, город, кузов, объём, топливо, мощность.
- Доставка данных: `window.opener.postMessage` (если открыто из AUTOGOOD)
  или `mobile.html#autogood-import=<json>`. Приём только от
  `https://(suchen|www|m).mobile.de`.
- **Закладка — копия кода на момент перетаскивания.** После изменений
  закладки её надо перетащить заново.

### 4.5 Анализ рынка
- **otomoto:** 8 страниц по 32 предложения равномерно по списку от дешёвых
  к дорогим (3 параллельно, через `r.jina.ai`). У каждого предложения есть
  реальное место в списке (`rank`, `marketTotal`).
- **mobile.de:** сервер `/mobilede/search` читает выборку в Chrome, когда
  доступен; при отказе одного источника остальные продолжают загрузку.
- **blocket.se:** выборка до 8 страниц по 50 через открытый API и `r.jina.ai`;
  пробег из mil переводится в км, цены SEK пересчитываются для сравнения.
- **График:** три рынка с отдельными цветами, точки открывают объявления.
  На графике цена заграничных предложений — оценка «na gotowo» в PLN,
  польских — цена объявления в PLN. Источники и курсы обозначены явно;
  P25/медиана/P75 рассчитываются по пригодным предложениям.
- **Статистика и таблица:** количество, минимум, максимум, медиана, P25–P75
  по источникам. Подозрительные предложения видны серыми, но исключены из
  статистики; список отражает точки графика. Логотип ведёт на портал,
  флаг/страна обозначают сравниваемый рынок.
- **Подозрительные предложения** (вне статистики и истории, серые пустые
  кружки на графике):
  - слова «uszkodzony, na części, do naprawy, po wypadku, cesja, przejęcie
    najmu/leasingu, Motorschaden, Unfall…» (без «bezwypadkowy», «unfallfrei»,
    «możliwy leasing»);
  - цена < 1/3 или > 3× медианы **машин того же года ±1**.
- **Сравнение конкретного авто:** распознанное объявление отмечается на
  графике; полный сценарий «это авто na gotowo против otomoto» ещё B3.
- **Отчёт для клиента:** картинка/PDF анализа и отдельного списка предложений.
  История цен вынесена на страницу 3, избранные поиски — на страницу 4.

### 4.6 История поисков, избранное, история цен
- Страница 1: история обычных поисков под формой; после изменения фильтров
  запись создаётся/обновляется с задержкой. Избранные поиски закреплены в
  общей полосе и доступны на странице 4; ★ добавляет/убирает избранное,
  не удаляя обычную историю. Выбор избранного остаётся на текущей странице.
- Выбранная запись истории/избранного + реальные изменения фильтров или
  сравниваемых рынков → «Gotowe» сохраняет изменения в ту же запись.

  «Odśwież dane») = **новая строка** с датой и временем на странице 3.
  Данные рынков хранятся в их валютах; для DE/SE сохраняется также оценка
  «na gotowo». Для каждой строки: количество,
  мин, P25, медиана, P75, макс, стрелки изменения к прошлой проверке

- Хранение: `localStorage` браузера (`autogood.mobile.marketHistory.v2`) —

### 4.6.1 Сохранность избранного и истории — ОБЯЗАТЕЛЬНЫЕ правила

Инцидент 2026-09-27: у владельца пропали избранные поиски/авто. Прочитать
хранилище Chrome с диска для восстановления не удалось (нет доступа).
Причины, найденные в коде (до исправления):

1. **Устаревшая вкладка затирала всё.** История читалась из `localStorage`
   один раз при открытии вкладки, а каждое изменение (в т.ч. **автоматическая
   запись каждого поиска**) записывало в хранилище весь массив из памяти.
   Две вкладки mobile.html (например, вторая открылась через закладку
   `#autogood-import=…`) → ★ в одной вкладке, потом любой поиск в другой →
   избранное из первой исчезало. Самый вероятный сценарий.
2. **Нечитаемая история = пустая история.** Любая ошибка чтения/разбора
   давала `[]`, и следующий авто-лог поиска перезаписывал хранилище.
3. **Переполнение `localStorage` (~5 МБ).** У каждой записи до сотен
   предложений; при переполнении запись просто не сохранялась.
4. **Другой адрес = другое хранилище.** `localStorage` привязан к адресу:
   `belovn1999-rgb.github.io`, `localhost:<порт>` (каждый порт отдельно),
   другой браузер/профиль Chrome — у каждого своё избранное. Очистка данных
   сайта / режим инкогнито тоже стирают его.

Что сделано (`src/mobile-market-analysis.js`) и что **нельзя ломать**:

- `refreshMarketHistory()` — **каждая** функция, меняющая историю
  (`createMarketSnapshot`, `updateMarketSnapshot`, `setHistoryPinned`,
  `deleteHistoryEntry`, `toggleCurrentHistoryFavorite`, `logSearchToHistory`),
  сначала перечитывает хранилище. Новая функция записи → тоже.
- Событие `storage`: изменения из другой вкладки сразу видны в этой.
- `storeMarketHistory` сначала пишет резервную копию избранного
  `autogood.mobile.marketFavorites.v1` (маленькая, без предложений), потом
  историю; при переполнении по очереди убирает списки предложений у старых
  и затем у всех **неизбранных** записей. Избранное не удаляется никогда.
- `loadMarketHistory` возвращает избранное из резервной копии, если в
  истории его нет. Нечитаемая история копируется в
  `autogood.mobile.marketHistory.broken.<время>` до любой новой записи.
- **Запрещено:** менять ключи хранилища без миграции старых; вызывать
  `localStorage.clear()`/`removeItem` для этих ключей; писать в хранилище
  массив, загруженный давно, а не перечитанный; фильтровать при загрузке
  записи так, что они потом перезапишутся (новое поле фильтра → записи без
  него должны читаться).
- Работать владельцу **только** с https://belovn1999-rgb.github.io/autogood-kalkulatory/mobile.html
  в одном и том же профиле Chrome; localhost — только для тестов.
- Полная защита (перенос между браузерами/устройствами, очистка данных) —
  только экспорт/импорт или сервер: бэклог B25, B26.

### 4.7 Курс и «na gotowo»
- Курс = курс калькулятора: **Walutomat, лучшая цена продажи EUR→PLN**
  (`AUTOGOOD_TURNKEY.calculatorRate()`), запасной — `data/exchange-rates.json`.
- `turnkeyDirect()` = формула вкладки «Zakup bezpośredni» калькулятора:
  авто×курс + осмотр и транспорт (+VAT 23%) + акциз по классу двигателя
  + комиссия AUTOGOOD (1829,27 + 1%, +VAT) + TO 150 + перевод 250.
  **Без регистрации, без скидки**, итог округляется до 50 PLN.
  Сверено с калькулятором.
- `turnkeyForListing()` берёт тариф доставки/осмотра по стране и индексу
  продавца и класс акциза по топливу/объёму.
- **Константы — копия `src/main.jsx`. Меняешь калькулятор — меняй и модуль.**
- **Курс с маржой калькулятора (с 09-28):** EUR = Walutomat + 0,02 zł, округление
  до гроша (`rateWithCalculationMargin` в `main.jsx`); SEK — та же маржа в
  пропорции (`currentRates()`). Этот курс помечен `calculator: true` и
  `data/exchange-rates.json` его больше не перезаписывает. Им считаются график,
  статистика и «na gotowo».
- **«~ na gotowo» в анализе (с 09-28, решение владельца; раньше «pod klucz»):** для каждого
  предложения mobile.de и blocket.se — `turnkeyAverage()`: формула калькулятора
  с **усреднёнными** доставкой 2 500 zł нетто и осмотром 1 500 zł нетто (не тариф
  продавца), акциз по классу двигателя (`engineClassFor`: топливо и объём
  объявления, иначе из фильтров; шведские «laddhybrid/el/bensin» понимаются),
  услуга AUTOGOOD (1 829,27 + 1%) × 1,23 = 2 250 zł + 1,23%, ТО 150 + перевод 250.
  Показывается в статистике, таблице предложений и подсказках. На графике
  иностранные точки и их медианы стоят **непосредственно** по цене «na gotowo»
  в PLN; прежней отдельной пунктирной медианы нет. История цен сохраняет
  медиану «na gotowo» для DE/SE (старые замеры получают оценку из прежней
  медианы). Для PL остаётся цена объявления. Под графиком — сноска о расчёте
  и **вывод из данных**: иностранная медиана «na gotowo» против медианы Польши,
  текст «taniej» или «drożej» по фактическому сравнению.

## 9. Риски и ограничения

- **Параллельные правки** одного файла несколькими агентами → конфликты;
  см. правила в разделе 2.
- `r.jina.ai` — бесплатный внешний прокси: ограничения/отказ = нет данных otomoto.
- Сервер mobile.de на quick tunnel — адрес меняется при каждом запуске.
- Закладку нужно перетаскивать заново после изменений.
- История и избранное в `localStorage`: не переносятся между браузерами/устройствами/адресами, пропадают при очистке данных сайта — до B25/B26 (см. 4.6.1).
- Цены объявлений ≠ цены сделок.

## 10. Глоссарий

- **Na gotowo** — оценка полной цены иностранного авто после доставки в PL
  для физлица; в анализе рынка доставка и осмотр усреднены, а не подтверждены
  по конкретному продавцу. Ранее интерфейс называл это «pod klucz».
- **Под ключ (pod klucz)** — стоимость авто, доставленного и готового в PL
  для физлица, по формуле «Zakup bezpośredni», без регистрации.
- **P25 / медиана / P75** — цена, ниже которой 25% / 50% / 75% предложений.
- **Проверка** — одна загрузка цен рынка (строка в «Historia cen»).
- **Закладка** — bookmarklet «AUTOGOOD ↦ mobile.de».
