## 0. Коротко

- **Сейчас — нет.** Бот платформы только присылает сообщения и понимает две команды: `/start` (подключиться) и `/stop`
  (отключиться). Всё остальное, что ему пишут, он молча пропускает.
- **Работу на платформе через Telegram сделать можно** — сводку по запросу, «проверить сейчас», вкл/выкл мониторинга,
  ★ и «оффер» кнопками под машинами, ссылку объявления → оффер или калькулятор, VIN → проверка, напоминания.
  Это 4–5 волн; почти всё без миграций, кроме напоминаний.
- **Менять код и саму платформу бот платформы не сможет никогда** — и не должен: у него нет доступа к коду и серверу.
  Для изменений с телефона есть приложение Claude: **Dispatch** и **Remote Control** (сессия идёт на Маке, вы пишете
  с телефона). Канал Claude Code в Telegram тоже есть, но он — исследовательская версия и опаснее (§4).
- Рекомендация: волны **Т0 → Т1 → Т2** (основа, мониторинг из Telegram, ссылка → оффер), потом **Т3** напоминания.
  Для правок платформы с телефона — Dispatch / Remote Control в приложении Claude, не Telegram.

## 1. Что бот умеет сейчас (по коду `main` 07.11)

| Что | Где в коде | Как работает |
|---|---|---|
| Ключ бота | `app/Telegram/TelegramBot.php` | вставляет администратор в «Настройки → Компания», хранится зашифрованным (`telegram.bot_token`) |
| Подключение человека | `app/Telegram/TelegramLink.php` | «Подключить Telegram» → `t.me/<бот>?start=<метка 30 мин>` → «Start»; у пользователя `users.telegram_chat_id`, `telegram_locale` |
| Чтение сообщений боту | `zrok:telegram:pull`, `routes/console.php` | **раз в минуту**, `getUpdates` с `timeout 0`, только `message` (не нажатия кнопок); понимает `/start <метка>`, `/start`, `/stop` |
| Сводка мониторинга | `Portals/Monitoring/MonitoringTelegram.php`, `TelegramLetter.php` | после проверок по расписанию, только при находках (новые, подешевели, Okazja, вернулись) или сбое; до 3 машин на подборку со ссылками; кнопки — только **ссылки** «Открыть: <подборка>» (до 5) |
| Дочитанный mobile.de | `MonitoringLateNotice.php` | второе сообщение, если расширение дочитало позже |
| Сбой проверки порталов | `Portals/Reading/PortalCanary.php` | администраторам, раз в день на портал (06:40) |
| Пауза робота VIN Check | `app/Vin/RobotAlert.php` | администраторам, с кнопкой-ссылкой на `/vin` |
| Меню бота | `TelegramBot::describe()` | команды `start` и `stop`, описание на RU / PL / EN |

Что из этого важно для будущего:

1. **Задержка до минуты.** Ответ на любое сообщение придёт только при следующем `zrok:telegram:pull`. Для оповещений
   нормально, для разговора — плохо. Нужен вебхук (§3, Т0).
2. **Кнопки сейчас — только ссылки.** Кнопки-действия («★», «Проверить сейчас») — это `callback_query`, бот их пока не
   читает (`allowed_updates = ['message']`).
3. **Названия команд в Telegram — только латиница** (`a–z`, `0–9`, `_`). `/сводка` в меню бота поставить нельзя.
   Решение: команды латиницей с русским описанием (`/summary — Сводка мониторинга`) и постоянная клавиатура внизу
   чата с русскими кнопками «📊 Сводка», «⏰ Напоминания» — они шлют обычный текст, бот его узнаёт.
4. Готовые «кирпичи» платформы, на которые бот может опереться: `MonitoringRunner::request()` (проверка вне расписания),
   `Digest` / `TelegramLetter::render()` (сводка), включение мониторинга (`Livewire/Dealers/Monitoring::updatedEnabled`),
   ★ машины (`toggleSaved`), «Просмотрено» (`markSeen`), оффер из объявления (`Offers/Index::createFromAd`,
   `OfferBuilder`), отчёт аукциона по ссылке (`AuctionReports::fromUrl`), калькулятор по ссылке (`/calculator?link=…`),
   очередь VIN Check, плашка «что не работает» (`Portals/ServerHealth`).

Чего **не стоит** делать в боте платформы ни в одной волне: удаление подборок, офферов, проверок; отправку чего-либо
клиенту; смену настроек фирмы, шаблона калькулятора, ключей; управление пользователями. Причина: украденный или
забытый открытым Telegram = доступ к этим действиям без пароля платформы.

### Безопасность — общие правила для всех волн

- Действия — только от имени пользователя, к чьему `telegram_chat_id` привязан чат, и только с его правами
  (свои подборки, свои офферы; администратор — как на сайте). Чужая метка кнопки → «нет доступа».
- Только личные чаты (группы бот уже пропускает — так и остаётся).
- Каждое действие из Telegram пишется в журнал сервера: кто, что, когда (отдельная таблица не нужна — вопрос 8).
- Подтверждение «Точно?» — у выключения мониторинга и у всего, что пишет данные, кроме ★ и «Просмотрено».
- `/stop` по-прежнему отключает всё сразу; на странице платформы — «Отключить Telegram».

## 3. Как это устроено (для разработки)

- **Вебхук вместо минутного опроса** (Т0). Telegram сам присылает каждое сообщение и нажатие на
  `https://tools.mantexlab.com/telegram/webhook`; платформа проверяет секрет, отвечает Telegram сразу, а саму работу
  ставит в очередь (`default`) — ответ менеджеру за 1–2 с. `setWebhook` вызывается при сохранении ключа в
  «Настройки → Компания», как сейчас ставится меню. Запасной путь при сбое — та же минутная команда, но она должна
  сначала снять вебхук (`deleteWebhook`): одновременно оба способа Telegram не позволяет.
- **Кнопки-действия**: `callback_data` до 64 байт — короткая случайная метка, за ней в Redis «пользователь, действие,
  объект», 7 дней. После нажатия — `answerCallbackQuery` («★ добавлено») и правка кнопок того же сообщения
  (`editMessageReplyMarkup`), чтобы не плодить сообщения.
- **Одна «точка входа»** `TelegramRouter`: команда / текст клавиатуры / ссылка / VIN / нажатие → свой обработчик.
  `TelegramLink` (подключение) остаётся как есть.
- **Языки**: всё на `telegram_locale` пользователя (RU / PL / EN), тексты — в `lang/*/dealers.php` → блок `telegram`
  (или свой файл `lang/*/telegram.php`, когда разрастётся).
- **Напоминания** (Т3): таблица `reminders` (`user_id`, `text`, `due_at`, `sent_at`, `done_at`, `remindable` — подборка,
  оффер или машина, необязательно), `zrok:reminders:send` раз в минуту в `routes/console.php`; разбор времени — свой
  класс с тестами на RU / PL / EN, без ИИ.

## 4. Чего бот платформы не может — и чем это делать

Бот платформы — часть платформы на сервере. У него нет доступа к коду, к GitHub, к `ssh` и к вам на Маке, поэтому
**менять код, дизайн, правила, выкладывать** он не может. Так и должно быть.

Для изменений платформы с телефона у Claude Code есть (проверено по документации `code.claude.com/docs`, 07.11):

| Способ | Как работает | Что нужно | Подходит для | Минусы |
|---|---|---|---|---|
| **Dispatch** (рекомендуем) | в приложении Claude на телефоне пишете задачу → она запускается сессией в приложении Claude на Маке | приложение Claude на телефоне, связанное с приложением Claude на Маке; Мак включён | «сделай правку X», «что висит невыложенным», «выложи по моему да» — как сейчас в чате, только с телефона | Мак должен быть включён и не спать (в приложении есть «не давать уснуть») |
| **Remote Control** | уже идущую сессию Claude Code на Маке продолжаете с телефона (приложение Claude или `claude.ai/code`) | подписка Pro / Max / Team / Enterprise (ключ API не подходит); в приложении на Маке — `/remote-control` в сессии или «Connect new sessions to Remote Control» в настройках | продолжить начатую работу, ответить на вопрос сессии, нажать «да, выкладывай» | Мак включён; переписка сессии хранится у Anthropic, пока подключено |
| **Канал Claude Code в Telegram** (Channels) | пишете в **отдельного** Telegram-бота → сообщение приходит в сессию Claude Code на Маке, ответ — в Telegram | исследовательская версия; Bun; сессия запущена в терминале с `claude --channels plugin:telegram@claude-plugins-official`; свой бот от @BotFather; привязка кодом `/telegram:access pair`, затем `/telegram:access policy allowlist` | короткие вопросы и задачи из Telegram | **нельзя тот же бот, что у платформы** (два читателя одного ключа отбирают сообщения друг у друга); пока сессия ждёт разрешения — стоит, или её запускают с пропуском разрешений; у сессии на Маке есть ключ `ssh` к серверу — кто получит ваш Telegram, получит и доступ к выкладке; терминал на Маке должен быть открыт всё время |

Вывод: **два разных Telegram-бота не нужны.** Бот платформы — для работы менеджеров с машинами и клиентами;
изменения платформы — приложением Claude (Dispatch или Remote Control): вход по учётной записи Claude, а не по
Telegram, и правило «выкладка только по вашему «да» в чате» сохраняется.
