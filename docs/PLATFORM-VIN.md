## 2. Правила для чатов VIN Check (CONFIRMED 20.10)

1. Все правила `PLATFORM-SEARCH.md` §2 действуют и здесь: нет слова AUTOGOOD на платформе; логику переписываем на
   PHP, код как есть не копируем; своя копия кода (`git worktree`), коммит только явными путями.
2. **Робот partslink24 на сервере — только после согласия шефа** по правилу платформы «partslink24 не
   автоматизировать» (её `CLAUDE.md`). До ответа — `ZROK_VIN_ROBOT=false`, отчёт загружается PDF.
3. **Одна проверка за раз на всю платформу** (просьба владельца 20.10, «очень важно»): своя очередь `vin` с одним
   процессом Horizon, замок partslink24 в задаче, пауза 7 с между проверками. Поднимать `maxProcesses` нельзя.
4. Логин partslink24 — один на платформу, только в `.env` сервера (`PARTSLINK24_COMPANY_ID`, `PARTSLINK24_USERNAME`,
   `PARTSLINK24_PASSWORD`). Пароли в чат и в git не выводить; Claude пароль не вводит — вносит владелец или администратор.
5. Каждое правило чтения отчёта — тест (положительный и отрицательный случай), как в исходной программе; правка
   чтения — сверка со старой программой на реальных PDF (0 расхождений), PDF клиентов в репозиторий не попадают.
6. Выкладка — только по «выкладывай» владельца; миграции базы — только по прямому «да, миграция». Перед выкладкой —
   варианты вида (макеты) на выбор владельца.
7. В коммите волны — контракт `docs/contracts/vin.md` и строка этапа 7 в `docs/board.md` платформы; здесь — статус
   волны (§5) и журнал `PROJECT_BRAIN.md` §8.

### 9.2 Изменения раскладки — одобрены владельцем 22.10 (все 7)

Решение 21.10 (вариант B) сохраняется: папка истории сверху, форма одной строкой, ниже результат слева и PDF справа
