## 1. Перед работой (обязательно)

1. Прочитай `docs/PROJECT_BRAIN.md`, **`docs/OFFER-PAGE.md` целиком** (особенно §2 решения,
   §4 правила текстов клиенту, §5 архитектура, §8 программа 06), `PROJECT-MOBILE.md` §2 и
   §4.6.1 (данные пользователя не теряются никогда).
2. `git fetch`, `git status -sb`, работа в своём `git worktree` от `origin/main`
   (в основной копии чужие правки). Код оффера: `src/offer*.js`, `oferta.html`, `oferty.html`,
   тест `scripts/offer.test.mjs`.
3. **Код чужих проектов не копируем** (у deal-finder, used-car-deal-finder лицензии нет) —
   только идея, пишем своё.
4. **Правила текстов клиенту (§4) действуют для каждого нового блока:** у утверждения
   виден источник («z ogłoszenia», «wg sprzedawcy», «sprawdzimy na oględzinach»); менеджер
   подтверждает флаги перед PDF; без непроверенных обещаний; дефис «-» на листах.
5. Ключи ИИ — **только на нашем сервере / в службе Mac**, не в браузере и не в репозитории
   (решение 10-05).

## 2. Порядок работы по каждому пункту

1. **Проверка у источника** — ссылка на GitHub, какие файлы смотреть; как это работает у них.
2. **Проверка у нас** — что уже сделано (у части пунктов многое уже есть, см. ниже).
3. **Вердикт и план** коротко владельцу: где на листе / в панели, что нужно от него.
4. После «да» — код, тест в `offer.test.mjs`, проверка вживую (оба входа: 06 и стр. 3, PL и RU,
   PDF), `ship`, `OFFER-PAGE.md` §0 / §7, `PROJECT_BRAIN.md` §8, статус в `REFERENCE-PROJECTS.md` §3.

**Рекомендуемый порядок:** без ИИ — **O9 → O8 → O3 (правила) → O6 (правила) → O2 → O12**;
затем **общий ИИ-слой** (§4) — **O4, O5, O3 и O6 из описания**.

## 3. Пункты без ИИ

### O9 — надёжность оценки цены

- **Источник:** [qwillemse/autoscout-analyser](https://github.com/qwillemse/autoscout-analyser) —
  README: вердикт («Great deal … Overpriced») только с доверительным диапазоном (ошибка по
  комплектации → модели → марке); [Dropio12/used-car-deal-finder](https://github.com/Dropio12/used-car-deal-finder)
  — README: сигнал только при **≥ 6 похожих**.
- **У нас уже есть:** `src/offer-market.js` — `MIN_SIMILAR = 6`, похожие год ± 1 / пробег ± 35 %,
  потом ± 2 / ± 60 %, < 8 — все страны; `src/offer.js` ~384 — «Tańsze niż X % z N podobnych
  ofert», ~467 плитка «Na tle rynku».
- **Сделать (только недостающее):** при расширенном поиске похожих (± 2 / ± 60 %, все
  страны) или 6–9 похожих — мягкая формулировка («orientacyjnie», без точного «X % poniżej
  mediany») и мелкая подпись «na podstawie N podobnych ofert z <kraje>, <data>»; в программе 06
  (рынка нет) — подпись источника оценки портала. Проверить и оба языка.
- **Готово, когда:** на 3 офферах с разной выборкой формулировка меняется правильно; тест.

### O8 — дни в продаже, снижения, «wróciło» в торге

- **Источник:** autoscout-analyser — `first_seen` / `last_seen`; [nyg/autoscout24-trends](https://github.com/nyg/autoscout24-trends)
  — вся история цены машины; Dropio12 — статус «relisted».
- **У нас уже есть:** `src/offer.js` ~646–665 — дни в продаже и «cena obniżona N× (−X %)»;
  ~786 — даты из объявления, Carvago и наших проверок; «Potencjał negocjacji*».
- **Сделать:** (1) статус **«wróciło»** — берётся из Monitoring (пункт M3 инструкции
  Monitoring, `docs/handoff/handoff-monitoring-reference-ideas-2026-10-11.md`); **не писать
  свою логику** — дождаться/переиспользовать M3; (2) в «Potencjał negocjacji» — строка-основание
  из этих фактов («w sprzedaży 74 dni, cena obniżona 2×, ogłoszenie wystawione ponownie»).
- **Зависимость:** M3. Без него — только (2) из уже имеющихся данных.

### O3 — «Co wiemy z ogłoszenia» (сейчас по правилам)

- **Источник:** [danyk20/deal-finder](https://github.com/danyk20/deal-finder) —
  `deal_finder/ai/questions.py`: вопрос за вопросом, ответ **только из данных объявления**,
  иначе «not stated»; `Listing.as_key_value_text` в `adapters/base.py` — все поля в одном тексте.
- **У нас уже есть:** `src/offer-ad.js` читает `owners`, `accidentFree`, `serviceBook`, гарантию,
  ТО (`hu`), состояние, «Bezwypadkowy» (OFFER-PAGE §3, §3а) — разбросано по блокам.
- **Сделать:** один компактный блок (или раздел «Ocena AUTOGOOD») — 5–6 строк:
  wypadek · historia serwisowa · właściciele · gwarancja · przegląd · uszkodzenia; у каждой
  значение + источник; нет данных → **«nie podano — sprawdzimy na oględzinach»**. Решение
  о месте на листе — владельцу (лист 1 переполнен: предложить 2 варианта).
- **Позже (ИИ, §4):** ответы из текста описания на те же вопросы.

### O6 — требования клиента: обязательные опции и основные параметры

- **Источник:** deal-finder — `deal_finder/ai/dealbreakers.py`: каждое требование отдельно;
  сначала текст, фото — только если текст молчит; **«не сказано» ≠ отказ**; ответ ✓ / ✗ / ?.
- **У нас:** опции и словари — `src/offer-equipment.js` (сильные опции, синонимы на DE/FR/NL/SE/RU);
  параметры авто — `offer-ad.js`; заметка клиента — история поиска Monitoring (B67 «+ notatka»).
- **Сделать:** в панели оффера «Wymagania klienta»: (1) **обязательные опции** — выбор из
  списка сильных опций (`offer-equipment.js`) + своё слово; (2) **основные параметры** —
  год od, пробег do, топливо, коробка, привод, бюджет «na gotowo». На листе — строка/блок
  «Pana wymagania»: ✓ (подтверждено объявлением), ✗ (противоречит — менеджер решает,
  показывать ли), ? («sprawdzimy») с источником. Сохранять в оффере; для стр. 3 — подставлять
  из избранного (фильтры поиска = параметры по умолчанию).
- **Позже (ИИ, §4):** «?» по опциям проверяет описание.
- **Готово, когда:** на 3 офферах галочки совпадают с ручной проверкой объявления; PL / RU.

### O2 — архив объявления (по выбору менеджера)

- **Источник:** autoscout24-trends — README: фото в Cloudflare R2 (WebP, без повторов),
  **сжатый снимок всей страницы**; хранение по объявлению.
- **У нас:** фото читаются при каждом PDF (`photoData` в `src/offer.js` ~1352), оффер —
  IndexedDB `autogood-offers` (`src/offer-store.js`, только добавление).
- **Сделать:** кнопка в панели «Zachowaj ogłoszenie» → менеджер отмечает: ☐ PDF całej strony
  ogłoszenia ☐ wszystkie zdjęcia. **Проверить варианты PDF страницы:** mobile.de — печать
  страницы Chrome импортера на Mac (CDP `Page.printToPDF`, импортер уже держит Chrome);
  остальные порталы — либо так же через Chrome службы, либо собственная «karta ogłoszenia»
  PDF из прочитанных данных (все поля, описание, все фото, ссылка, дата) — сравнить и
  предложить владельцу. Хранение — IndexedDB оффера (оценить объём: 30 фото × ~300 КБ;
  предупреждать о месте), позже — сервер. Скачать архив одним файлом (zip или PDF).
- **Зачем:** объявление исчезает после продажи — остаются доказательства того, что заявлял
  продавец (для осмотра, торга, спора) и можно пересобрать PDF оффера.
- **Готово, когда:** архив открывается после удаления объявления (проверить на снятом);
  данные пользователя не теряются (4.6.1).

### O12 — альтернативы и оффер на 2–3 авто

- **Источник:** autoscout-analyser — README: похожие машины по разнице цены, ссылки на 3 лучших
  активных.
- **Сделать:**
  1. **Monitoring (стр. 3):** у объявления — «3 alternatywy» (те же параметры, ближайшие по
     цене «na gotowo», активные) в панели менеджера; кнопка «Przygotuj ofertę» у каждой.
     Согласовать с чатом Monitoring (их файл — `src/mobile-monitoring.js`).
  2. **Шаблон «Porównanie 2–3 aut»:** выбор 2–3 машин (галочка «Do oferty» в Monitoring или
     2–3 ссылки в программе 06) → `oferta.html` в режиме сравнения: лист 1 — колонки
     (фото, «na gotowo», 6 параметров, топ-опции, вердикт, место на рынке, ✓ требований O6),
     лист 2 — процесс и контакт один раз; расчёт у каждой машины. **Макет показать владельцу
     до кода** (2 варианта раскладки).
- **Зачем:** клиент выбирает из нескольких вариантов на одном листе; быстрый ответ на «а есть
  ещё что-то?».

## 4. Общий ИИ-слой (O4, O5, O3 и O6 из описания)

**Сначала — решение владельца** (решение 10-05 «ИИ потом, ключ на сервере» теперь
выполняется): предложи короткий документ решения (скилл `architecture`): где работает ИИ —
служба на Mac рядом с импортером (временно) или наш сервер / Cloudflare Worker с секретом;
провайдер и модель (по скиллу `claude-api`, с **оценкой цены одного оффера** и выбором между
более дешёвой и более точной моделью); что уходит в ИИ (только публичный текст объявления и
список требований, **без персональных данных клиента**).

**Как устроить (по deal-finder):**
- **Один вызов на объявление** → структурированный ответ: перевод (O4), ответы на вопросы O3,
  предупреждения O5 с цитатами, проверка требований O6 (✓ / ✗ / ?). Кэш по объявлению +
  тексту — повторное открытие оффера не платит.
- **Текст сначала, фото — нет** (O7 не выбран).
- **Каждое требование — отдельно**; «не сказано» = «?», а не «✗» (`dealbreakers.py`: при совместной
  проверке модель путала требования).
- **ИИ никогда не блокирует оффер** (deal-finder `_safe_enrich`: при ошибке всё собирается как
  сейчас; панель пишет «analiza AI niedostępna»).
- **Каждое утверждение ИИ — с цитатой из объявления и подтверждением менеджера** (правило §4);
  на листе пометка «wg opisu sprzedawcy».

### O4 — перевод описания
- **Источник:** deal-finder `deal_finder/ai/translate.py` + README (перевод на язык получателя;
  при недоступном ИИ — без перевода).
- **Сделать:** панель «Opis sprzedawcy — tłumaczenie» (язык оффера PL / RU); на лист — 2–3
  предложения по выбору менеджера с «wg sprzedawcy».

### O5 — предупреждения из описания
- **Источник:** autoscout-analyser — README, `/explain`: ИИ читает описание и ищет
  предупреждения (смотанный пробег, нет ТО); запасной текст при недоступном ИИ.
- **У нас:** правила `src/offer-verdict.js` (флаги с цитатами на DE/EN/FR/RU/NL/SE, отрицания).
- **Сделать:** ИИ **дополняет** правила (перефразы, любые языки), не заменяет; новые флаги
  помечены «AI», менеджер подтверждает; сверить на тех же 40 объявлениях C-HR, что и правила
  (OFFER-PAGE §0 волна 4) — ложных срабатываний не больше, чем у правил.
