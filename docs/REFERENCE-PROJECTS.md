## 1. danyk20/deal-finder — разобран по коду

https://github.com/danyk20/deal-finder · Python, FastAPI, APScheduler, SQLite,
Ollama · 6 порталов Швейцарии (AutoScout24.ch, AutoUncle, tutti, Ricardo,
Autolina, Facebook) · активен (06.10.2026) · **лицензии нет**.

Как работает: «watch» (сохранённый поиск: марка, модель, цена, год, пробег,
ключевые слова, свободный текст «обязательно») → по расписанию все порталы
**параллельно** → каждый портал сам переводит объявления в общий формат
`Listing` → наши фильтры применяются ещё раз поверх ответа портала («портал
фильтрует неровно — правда у нас») → ИИ-проверка «обязательно» → дубли между
порталами → новые (не в `seen`) → уведомление в Telegram (по одному, с фото)
или одним письмом → в `seen` пишется только то, что **доставлено**.

### Что у нас уже есть (не брать)
- Новые/исчезнувшие, `seen`, сравнение только с проверкой тех же параметров (4.6.3).
- Дубли mobile.de ↔ AutoScout24 по цене + пробегу + году — **точнее**, чем их
  «название + цена».
- Mac как сервер через LaunchAgent, догон пропущенного запуска (MONITORING-SERVER §6).
- Неполный список помечается «?», ответ одного портала не ломает остальные.
- Жёлтое «!» о фильтрах, которые портал не принимает.

### Что стоит взять (по пользе)

| # | Идея | Зачем нам | Где | Сложность |
|---|---|---|---|---|
| R1 | **Уведомления о новых машинах** (Telegram и/или письмо утром): по одной на машину с фото, ценой, «na gotowo», % к медиане. Помечать «увидено» только после доставки, иначе повтор в следующий раз | Сейчас новое видно, только если открыть стр. 3. Менеджер узнаёт о выгодной машине раньше конкурента | Monitoring (B43) | средняя |

Меньше пустых звонков дилерам | Monitoring, оффер (B71) | средняя (нужен ИИ: локальный Ollama бесплатно на Mac с 16+ ГБ или платный API) |
| R3 | **Перевод описания + ответы на стандартные вопросы** («была ли авария», «сервисная история», «что известно о дефектах», «когда можно забрать») только из данных объявления; нет ответа → «nie podano», без выдумок | Готовый текст для звонка дилеру и для оффера клиенту на PL/RU | Monitoring, `oferta.html` | средняя |
| R4 | **«Почему отсеяно»**: список объявлений, которые портал вернул, но наши фильтры отбросили, с причиной («rok 2018 < 2019», «przebieg 182 000 > 150 000») | Доверие к фильтрам: видно, что портал прислал лишнее и мы его убрали, а не потеряли | Monitoring, стр. 2 | малая |
| R5 | **Повторная проверка фильтров у себя** после ответа портала (год, пробег, цена, мощность) — если ещё не везде | Портал, проигнорировавший фильтр, не портит медиану и статистику | анализ, Monitoring | малая (сначала проверить, где уже делаем) |
| R6 | **Двухфазное чтение**: дешёвый список → подробности (опции, описание, фото) только для **новых**, не больше N за прогон, от новых к старым | Подробности нужны R1–R3, но не для всех 300 машин | Monitoring | малая |
| R7 | **Ежедневная живая проверка парсеров** (`health_check` на портал: известный поиск должен вернуть > 0 и нужные поля) + письмо владельцу при поломке | Портал меняет вёрстку — узнаём сразу, а не от менеджера | CI / раннер | малая |
| R8 | **Тесты на сохранённых ответах порталов** (fixtures JSON/HTML) для каждого парсера | Лекарство от «чинишь под одну машину» | `scripts/` | малая |
| R9 | **Будить Mac к 9:25** (`pmset repeat wakeorpoweron`) | Вариант Б: спящий Mac в 9:30 ничего не проверит | Mac владельца | 5 минут |
| R10 | Режимы прогона: «пробный» (без записи и уведомлений), «тест отправки» (всё как новое, проверить вид письма/Telegram) | Безопасно настраивать мониторинг | Monitoring | малая |

**Не брать:** дубли по «название + цена» (наши точнее); обход защиты
(Camoufox у Ricardo, вход в Facebook); Facebook Marketplace (риск блокировки
аккаунта).

## 4. Общий вывод для инфраструктуры (B43/B73)

Три проекта запускают мониторинг **без своего сервера**: GitHub Actions по
расписанию (avby-bot, Dropio12) или Cloudflare Cron/Supabase pg_cron
(Dropio12, cenomierz). У нас GitHub Action уже обновляет курсы (B12). Порталы,
которые читаются через наш Worker (otomoto, AutoScout24, Marktplaats, 2dehands,
Kleinanzeigen, ParuVendu, Blocket) и av.by (открытый API), могли бы
проверяться по расписанию **в облаке**, а Mac (или будущий Mac mini) нужен
только для mobile.de. Проверить при решении B73.
