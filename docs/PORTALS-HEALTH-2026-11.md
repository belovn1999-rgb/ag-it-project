## 4. Самоконтроль раздела

**Что было.**
- У старой программы — утренняя проверка порталов в GitHub Actions (M9, письмо при сбое).
- На платформе — плашка администратора «Co nie działa na serwerze» (3а.27): почта, mobile.de / av.by давно не читались,
  ссылки клиента.
- Сторож мониторинга `zrok:monitoring:watch` — только письмо, а почта сервера не настроена.

**Что сделано (`83846852`, не выложено).**
- **Плашка администратора** (`ServerHealth`) — новые строки, только когда беда есть, на языке экрана:
  - «Сводки мониторинга не доходят до N из M сотрудников» — с причиной: нет ни почты, ни Telegram / Telegram не
    подключён / нет адреса;
  - «Расширение Mantexlab Tools не на связи больше 24 ч у N из M» — у владельцев мониторинга с mobile.de;
  - портал на паузе после отказов (до ЧЧ:ММ);
  - 3 чтения подборок подряд не удались — с датой и причиной;
  - беды сторожа мониторинга — до 5 строк и «ещё N»;
  - итог ежедневной проверки.
- **Ежедневная проверка** `zrok:portals:health` (`PortalCanary`):
  - **Что читает.** 12 порталов сервера (otomoto, AutoScout24 ×6, Marktplaats, 2dehands, Kleinanzeigen, Blocket,
    ParuVendu), по одной первой странице эталонного поиска VW Golf 2019–2021. Паузы 3–8 с, общий замок и пауза
    портала. Портал на паузе не трогается.
  - **Что не проходит.**
    - Меньше 5 объявлений.
    - Цена, год или пробег — меньше чем у 70–80 % объявлений.
    - Ссылка — меньше чем у 95 % объявлений.
    - Топливо и мощность — меньше чем у 70 % объявлений. Только там, где портал их показывает.
    - «Golf» в названии или год 2019–2021 — меньше чем у 70–80 % объявлений: портал подменил выдачу, как otomoto в F10.
    - Число объявлений упало в 3 раза или выросло в 3 раза со вчерашней проверки.
  - **Куда пишет.** Запись — `portal_reads` с `mode = health`, без подборки: «Анализ» и счёт отказов подборок её не видят.
    Удаляется вместе со старыми чтениями.
  - **Как сообщает.**
    - Непрошедшая проверка — строка плашки: «Проверка порталов 06.11 06:40: Marktplaats — Ошибка чтения: …».
    - Не проходила 36 ч — тоже строка.
    - Telegram администраторам — отдельным выключателем, раз в день на портал.
  - **mobile.de и av.by не трогает** (их читает только браузер).
- **Включение — по «да» владельца** (в `.env` сервера, без миграций):
  - `ZROK_PORTALS_HEALTH=true` — проверка каждый день в 06:40 по Варшаве (`ZROK_PORTALS_HEALTH_AT`). Вручную:
    `php artisan zrok:portals:health --force`, один портал — `--portal=otomoto`.
  - `ZROK_PORTALS_HEALTH_TELEGRAM=true` — Telegram администраторам при сбое. Дойдёт, только когда в «Настройках → Компания»
    есть ключ бота и администратор нажал «Подключить Telegram».
  - Цена проверки — 12 запросов в день, по одному на портал. Это меньше одного «Анализа».

## 5. Зависимость от Мака и браузера менеджера

- **mobile.de.**
  - Сервер mobile.de не читает. Читает расширение «Mantexlab Tools» 0.3.0 в Chrome менеджера: раз в минуту оно спрашивает
    задания и читает выдачу в фоновой вкладке.
  - Сейчас расширение не на связи с 26.10: у подборок с mobile.de мониторинг идёт без него. Сводка ждёт mobile.de
    до 30 мин, но только если расширение было на связи за последние 7 дней — значит, сейчас не ждёт. В сводке и на экране
    честно стоит «mobile.de не прочитан».
  - Теперь это видно и на плашке администратора («Расширение… не на связи больше 24 ч»).
- **av.by.**
  - Сервер получает 403, поэтому читает браузер менеджера: страница платформы шлёт ответы API av.by.
  - Без открытой платформы av.by не читается; плашка пишет «давно не читался».
  - 06.11 cars.av.by показал капчу 468. По правилу это стоп, обходить не будем.
- **Варианты без обхода защиты** (HYPOTHESIS, решает владелец):
  1. **Один «постоянный» Chrome в офисе.** Компьютер, который не выключается, с входом в платформу и расширением 0.3.0.
     Он читает mobile.de всех мониторингов утром, а платформу держит открытой для av.by. Самый дешёвый вариант,
     работает сразу. Минус: компьютер и Chrome должны быть включены к 9:30.
  2. **Расширение у нескольких сотрудников.** Сейчас задание берёт расширение владельца подборки. Доработка: брать задание
     любым расширением компании на связи. Тогда мониторинг не встаёт, когда один менеджер в отъезде. Это работа на 1–2 дня
     (3а.32 / 3б.24).
  3. **Громко, когда не читается.** Строки плашки сделаны (3а.65); Telegram администратору при «расширение не на связи
     больше суток» — тем же выключателем, что ежедневная проверка (работа на полдня, если владелец захочет).
  4. Чего **не** делаем: mobile.de и av.by с сервера через подставные адреса, «невидимый» браузер, решение капч.
